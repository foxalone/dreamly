# SEO Возможности

Адрес: `/app/profile/admin-dashboard?tab=SEO_OPPORTUNITIES`.
В существующей админке откройте кнопку «🚀 SEO Возможности».
Интерфейс только на русском по требованию владельца; публичные страницы сохраняют свои шесть языков.

## Первый отчёт

1. В Google Search Console откройте «Эффективность → Результаты поиска».
2. Выберите 28 **завершённых** дней, тип поиска Web. Используйте одинаковые фильтры страны, устройства и вида поиска для всех сравниваемых отчётов.
3. Экспортируйте CSV (ZIP с отдельными таблицами) или Excel XLSX.
4. Нажмите «📂 Загрузить данные Google», выберите файл. Если дат в файле нет, укажите фактические начало и конец периода из GSC.
5. После загрузки откройте «Возможности». Если нет подходящих страниц, выберите «Все страницы».
6. Нажмите «✨ Улучшить страницу». Заголовок и описание можно изменить, отклонить или отдельно применить. Применение явно публикует только выбранное поле для выбранного URL/языка.
7. В «📊 Результаты улучшений» можно отменить каждую правку. Если одно поле менялось несколько раз, отменяйте с последней правки.

CSV: запятая, точка с запятой и табуляция; UTF-8 и UTF-16LE. Распознаются основные заголовки GSC на шести языках, имена файлов произвольные. CTR пересчитывается из кликов и показов. Позиция взвешивается по показам. ZIP не извлекается на диск. Максимум: 4 МБ загрузки, суммарно 32 МБ распакованных данных (включая внутренний XLSX), 100 файлов в архиве, 20 000 строк и 5000 страниц. XLS нужно предварительно пересохранить в XLSX.

Таблицы Pages, Queries и Dates независимы. Их показатели никогда не складываются друг с другом. Для сводки предпочтительна таблица Dates, затем Pages, затем Queries. Данные страниц с разбивкой по запросам могут быть неполными из-за скрытых GSC запросов.

Обычные отдельные таблицы Pages и Queries не содержат связи между URL и запросом. Для анализа такой связи загрузите дополнительный CSV/XLSX с колонками Page, Query, Clicks, Impressions, Position (и Date, если есть). Отметьте «Дополнительный URL + Query» и выберите тот же период. Дополнение привязывается к выбранному основному отчёту; используется последнее дополнение, без выдуманного объединения по словам. При его загрузке основной отчёт остаётся выбранным.

## Расчёты и ограничения

- По умолчанию: позиция 6–15, от 300 показов, CTR минимум на 10% ниже сопоставимых страниц. Все эти пороги доступны в интерфейсе.
- Сопоставимы страницы того же языка на позициях ±2, у каждой минимум 100 показов; нужны минимум три другие страницы. При недостатке данных ожидаемый CTR не придумывается.
- Приоритет учитывает запас CTR, показы, близость к верхним позициям и надёжность выборки. Это порядок работы, а не прогноз дополнительных кликов.
- Последние 28 дней выделяются только из точного 28-дневного отчёта или ежедневных данных страниц с покрытием периода. Многомесячные итоги не делятся пропорционально дням.
- Сравнение сводки: предыдущий равный соседний период, если он загружен. Фильтры и тип поиска обязан сохранить одинаковыми администратор: агрегированный экспорт не всегда содержит их описание.
- Результаты: 28 дней до даты изменения и 28 после, без дня изменения. Неполный период, отменённые правки, другие изменения в соседние даты и менее 300 показов дают недостаточно данных. Порог заметности кликов учитывает абсолютное изменение, 10% и приближённый шум выборки. Это описательный индикатор, не статистическое доказательство причинности.
- Для истории показываются 20 последних изменений и доступны 60 последних импортов. Для каждого окна проверяются максимум два наиболее подходящих отчёта, сначала точное совпадение периода. Старые документы остаются в Firestore.
- AI-анализ и автоматическое применение поддерживают существующие канонические страницы словаря, вариаций и сочетаний на en/es/ar/pt/de/ru. Хабы, руководства и прочие URL видны в таблице, но требуют ручной оптимизации.
- Содержание и внутренние ссылки — редактируемые/отклоняемые задания для ручной редакции исходных страниц. Модуль публикует только title и meta description. Внутренние ссылки выбираются из существующих связанных страниц того же языка. Если доступных ссылок меньше трёх, показывается меньше.
- Сохранённый анализ открывается повторно без нового вызова AI. «Повторить анализ ИИ» доступен после отмены применённых полей; он обновляет неприменённый черновик. Анализ использует максимум 50 связанных строк запросов. Устаревшие предложения не перезаписывают более новые метаданные.

## Сервер и хранение

Используются существующие Firebase Admin настройки, проверка `requireAdmin`, модель `DREAM_ANALYSIS_MODEL`, ключ `ONEIRO_OPENAI_API_KEY` (резервный `OPENAI_API_KEY`). Новый провайдер и доступ GSC OAuth не требуются: данные загружаются вручную.

Коллекции:

- `seo_reports/{id}`: период, имя, дата импорта, предупреждения. `chunks` — подколлекция по 200 строк в документе. Импорт сохраняется одной атомарной batch-записью.
- `seo_analyses/{hash}`: сохранённые рекомендации и решения по отдельным полям.
- `seo_page_overrides/{hashURL}`: только выбранные метаданные конкретного URL/языка. Читаются при серверной генерации metadata, имеют приоритет перед текущим CTR-экспериментом. Шаблоны, hreflang, canonical, OG, JSON-LD и sitemap не меняются.
- `seo_changes/{id}`: исходное/новое значение, дата, связь с анализом и состояние отмены.
- `seo_limits/{admin_action}`: ограничение AI до 30 новых вызовов в сутки и интервал 15 секунд; импорт до 50 в сутки с интервалом 3 секунды. Неуспешные попытки тоже расходуют лимит.

Новые коллекции закрыты существующим завершающим правилом Firestore `allow read, write: if false`. Доступ — только серверный Admin SDK после проверки администратора. Дополнительные индексы не нужны: запросы используют только одно поле сортировки. Запись метаданных и отмена выполняются транзакциями. После записи вызывается `revalidatePath` публичного URL; обновлённое поле появляется в серверном HTML после следующей генерации страницы. При ошибке чтения Firestore рендер не кэширует пустое значение поверх сохранённой правки.

Лимит файла 4 МБ выбран с учётом ограничения размера запроса Vercel. Нет записи загруженных файлов на диск, внешнего скачивания URL или выполнения HTML из отчётов/ответов AI.

Локальные проверки:

```sh
npm run typecheck
node --import tsx --test lib/seoOpportunities.test.ts
```

Для полной проверки импорта, AI, публикации и отмены требуется вход под существующим администратором и рабочие Firebase/OpenAI настройки. Автоматического деплоя модуль не выполняет.

## История и выполненные задачи

Раздел «🕘 История» показывает сохранённые анализы по 20 записей с кнопкой «Показать ещё». Открытие идёт через защищённый GET API, без вызова OpenAI, в том числе для старого отчёта. Старые анализы, созданные до добавления истории, также доступны. Последний открытый анализ запоминается в браузере для текущего администратора и восстанавливается после перезагрузки. История доступна и с другого устройства.

У заданий по содержанию и ссылкам есть сохраняемые в Firestore статусы «Ожидает решения», «Передано агенту», «Выполнено», «Отклонено» и даты передачи/выполнения. После фактического изменения исходников нажмите «Отметить выполненным»; копирование промпта не подтверждает выполнение. «Вернуть в работу» снова делает пункт доступным. Выполненные и отклонённые пункты исключаются из индивидуальных и общих промптов.

При повторном анализе предыдущая версия сохраняется в той же коллекции `seo_analyses` как архивная запись. Её задачи и решения можно просмотреть в истории, но старые метаданные из архивной версии повторно применить нельзя. На странице возможностей для URL из последних 20 анализов предлагается открыть сохранённый анализ; остальные доступны через историю. Существующая история публикаций и отмены метаданных по-прежнему находится в «Результатах улучшений».
