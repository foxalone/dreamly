# Dreamly i18n

The public site is written natively in **six** languages. English URLs stay unprefixed for SEO. The other five use a prefix.

| Locale | URL | Voice |
|---|---|---|
| `en` | `/dreams/snake` | US English (source) |
| `es` | `/es/dreams/snake` | Latin American Spanish |
| `ar` | `/ar/dreams/snake` | Modern Standard Arabic, RTL |
| `pt` | `/pt/dreams/snake` | Brazilian Portuguese |
| `de` | `/de/dreams/snake` | Standard German |
| `ru` | `/ru/dreams/snake` | Natural literary Russian |

`/en/...` redirects 308 to the unprefixed English URL. Do not auto-redirect `/` by `Accept-Language`.

Exempt from prefixes: `/api/*`, `/_next/*`, admin dashboard, files with extensions.

Public gallery: `/gallery` (and `/es/gallery` …). English stays unprefixed.

## Where copy lives

| Kind | English | Other locales |
|---|---|---|
| UI chrome, nav, home, journal labels | `lib/i18n/messages/en.ts` | `messages/{es,ar,pt,de,ru}.ts` + `types.ts` |
| Categories | `lib/i18n/categories.ts` | same file |
| Dictionary templates (4 lenses, FAQ, scenarios) | `lib/dream-dictionary.ts` | `lib/i18n/templates.ts` |
| Symbol names / summaries / focuses | `lib/dream-dictionary.ts` | `lib/i18n/seeds/{es,ar,pt,de,ru}.ts` (one per dictionary slug) |
| Hand-written entry pages (optional) | `SECTION_OVERRIDES` / `META_OVERRIDES` in `lib/dream-dictionary.ts` | `lib/i18n/entry-overrides/{es,ar,pt,de,ru}.ts` |
| Guides | `lib/dream-guides.ts` | `lib/i18n/guides/*.ts` + `localize-guides.ts` |
| Faith hubs | `lib/i18n/hubs.ts` | same file |
| Legal | `lib/i18n/legal.tsx` | same file |

Helpers: `localePath`, `LocaleLink`, `getMessages`, `getLocalizedEntry`, `getLocalizedGuide`, `localeMetadata`.

## Adding a dictionary symbol

1. Add the English entry (and variations) in `lib/dream-dictionary.ts`.
2. Add the same slug to **all five** seed files:
   - parent: `{ name, summary }`
   - variation/combo: `{ name, focus }`
3. Names stay lowercase common phrases except German nouns (`Schlange`).
4. Do not apply English `SECTION_OVERRIDES` to other locales — templates generate native sections from the seed.
5. For a hand-written page in another language, add `{ seoTitle, seoDescription, sections }` under the slug in `lib/i18n/entry-overrides/{locale}.ts`. Write it natively for that audience (idioms, local references, scripture numbering of that tradition) — never a translation of the English page. Sections you omit fall back to the templates.
6. Combination pages (`COMBINATIONS`) may set `name` when the English title needs articles (`snake and a crocodile`).
7. Slug in the URL stays English.

### Inline links in dictionary and guide prose

- Write `[label](/dreams/slug)`; `LinkedText` renders it with the locale prefix. Only dictionary slugs, guide slugs, `/dreams` and its hubs become links.
- Dictionary entries: never in paragraph `[0]` of a section (quick symbol cards, lenses and image prompts read it as plain text), and never in FAQ or scenarios (they feed JSON-LD).
- `lib/entryOverrides.test.ts` and `lib/guideLinks.test.ts` enforce this for every locale.

## Adding a guide or hub page

1. English guide in `lib/dream-guides.ts`.
2. Native article (same section/FAQ count) in every `lib/i18n/guides/*.ts`.
3. Route: English `app/dreams/{slug}/page.tsx`; other locales are served by `app/[locale]/dreams/[symbol]/page.tsx`.
4. Add the path to `app/sitemap.ts` hub list if it is new.

## Adding any other page

1. Build a locale-aware view (`locale` prop + `getMessages` / localized data).
2. English route unprefixed; `app/[locale]/...` wrapper for `es|ar|pt|de|ru`.
3. `generateMetadata` must call `localeMetadata(unprefixedPath, locale)` for hreflang.
4. Internal links: `LocaleLink` or `localePath(href, locale)`.
5. Sitemap: include all six URLs.

## App / AI

`POST /api/dreams/analyze` accepts `lang`: `en|es|ar|pt|de|ru|he`. The journal sends the active UI locale. Analysis must be written in that language.

## Quality

Rewrite as a local editor, not a calque. Dreams are reflection, not diagnosis or prophecy. Keep Dreamly product mentions. Arabic uses Noto Sans Arabic (`html.locale-ar`).
